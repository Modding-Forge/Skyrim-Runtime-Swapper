= Automatic and Persistent Modes

Skyrim Runtime Swapper chooses the storage mode and recovery location automatically.
There is no vault path field, browse button, configuration value, or command-line override.

The decision considers the game filesystem, physical storage type, stable volume identity, recovery-vault location, ownership, permissions, free space, and synchronization support.

== Automatic

Automatic mode is used when the game is on trusted internal storage with native durability:

* Internal NTFS on Windows
* Internal ext4, XFS, or Btrfs on Linux

When starting from the source state without a persistent target active, the target runtime is activated for one Skyrim session and Skyrim 1.7.104 is restored after the game exits.
An existing verified target is not automatically restored merely because the storage supports Automatic mode; see xref:faqs.adoc#already-downgraded[Already-downgraded installations].

What to do:: Launch through `skse64_loader.exe` normally.

== Persistent only

Persistent-only mode is used for storage that is local and recoverable but not safe for automatic session restoration:

* External USB SSDs and HDDs
* Removable drives
* SD and microSD cards
* External NTFS, ext4, XFS, or Btrfs
* Internal or external exFAT

A stable target identity and a durable recovery vault on a different volume are required.
An external drive is not automatically supported regardless of its filesystem; an unsupported layout such as a native ZFS dataset remains blocked.
The target remains active until the user selects *Restore Skyrim 1.7.104* in the manual control panel.

What to do:: Read the displayed game-volume and recovery-vault descriptions, select *Downgrade persistently*, and retain the recovery vault until the manual restore is complete.

== Persistent with warning

This mode is used when storage is local and has a stable identity, but its filesystem or storage bus cannot be fully classified.
Common examples include:

* Kernel `ntfs3` on Linux
* `ntfs-3g` or `fuseblk`
* ReFS, FAT32, ext2, ext3, or another unclassified local filesystem
* A fixed drive whose physical connection cannot be identified reliably

Recovery files are verified, but a power loss may leave the game directory requiring manual recovery.

What to do:: Continue only after reading the warning. Select *Downgrade persistently anyway* to record explicit risk acceptance for this transaction.

.Persistent-with-warning confirmation with an additional power-loss warning and explicit risk acceptance.
image::persistent-warning-dialog-windows.png[Persistent downgrade dialog showing a ReFS game volume, an internal NTFS recovery vault, the manual recovery warning, and the Downgrade persistently anyway button]

NOTE: This screenshot uses example paths and volume descriptions. The dialog keeps the title *Persistent downgrade required*; the additional warning and *Downgrade persistently anyway* button distinguish this mode from *Persistent only*.

== Hard blocked

Hard blocked means Skyrim Runtime Swapper cannot guarantee a recoverable write.
No downgrade button is offered and no managed game file is changed.

Typical causes include:

* Network storage such as SMB, CIFS, or NFS
* DrvFS or a `9p` mount
* A volatile filesystem such as `tmpfs`
* No stable target or recovery-volume identity
* Native ZFS datasets, whose persistent identities are not currently supported
* No durable independent vault for an external or uncertain target
* Insufficient free space
* Unsafe ownership, permissions, symlinks, junctions, or reparse traversal
* A missing or changed active vault
* A missing or invalid native Linux sidecar
* Unrecognized or modified Skyrim source files

What to do:: Read both the user-facing message and *Technical reason*, then follow the matching entry in xref:troubleshooting.adoc[].

.Hard-blocked dialog for a network target, with the reason and diagnostic-log button.

NOTE: This screenshot illustrates the network-target case. Other blocked setups show their own reason. Use *Copy logs* when requesting help; there is no button to bypass the block.

== Example setups

[cols="2,1,3",options="header"]
|===
|Game location
|Expected mode
|Result

|Internal Windows NTFS drive
|Automatic
|Session target with automatic restore

|Internal Linux ext4, XFS, or Btrfs
|Automatic
|Native session target with automatic restore

|External NTFS SSD
|Persistent only
|Manual restore from a different durable vault

|External exFAT SSD
|Persistent only
|Manual restore from a different durable vault

|Internal Linux `ntfs3`
|Persistent with warning
|Explicit confirmation and manual restore

|Network share
|Hard blocked
|No managed file is changed

|External game drive with no suitable separate recovery storage available
|Hard blocked
|SRS cannot select a safe recovery location
|===

[IMPORTANT]
====
Persistent permission accepts uncertainty on the game target only.
It never overrides a missing, unsafe, or unverifiable recovery source.
====
